#+title: table-pretty — display-only pretty rendering of pipe tables
#+options: toc:2

* What it is

=table-pretty= renders markdown and org pipe tables as a
wrapped, box-drawing "pretty" view *on top of* the canonical raw table
text — and toggles between that pretty view and the raw source in
place.  It is the table analogue of inline images (=\[[file:img.png]]=)
or =org-latex-preview=:

- The buffer text is always the **canonical** raw pipe table.  Nothing
  is ever rewritten.
- A display overlay shows a pretty rendering (wrapped to the window,
  Unicode box-drawing borders by default).
- One command flips the overlay off to reveal/edit the raw source, and
  back on to re-render.
- Because the buffer is canonical, export / copy / share / push-to-GitHub
  / send-to-LLM always see a valid, single-row-per-record table.

This is deliberately *not* in-buffer table wrapping.  Earlier
experimentation (see =.scratch/PLAN.md=) mutated the buffer text into
wrapped form, but pipe-table syntax has no row-spanning, so wrapped
continuation rows render as extra blank data rows under any real
markdown/org exporter — semantically broken the moment the text leaves
Emacs.  =table-pretty= keeps the buffer correct and makes the pretty
view a disposable display layer.

* How it works

** Overlay model (per raw line, whole-table toggle)

One display overlay per raw line (so =C-n= walks raw lines and big
tables scroll naturally).  The toggle is whole-table: toggling adds or
removes *all* of a table's per-line overlays together.  Point can rest
on the raw lines behind the display (the overlay is =read-only=-free
and *not* =intangible=), so you can scroll through a tall table.

State is **overlay presence** — no bookkeeping.  "Is this table
pretty?" is just "does it have =table-pretty-display= overlays?"

** Editing reveals raw automatically (org-latex-preview pattern)

Pretty overlays carry =modification-hooks= that remove the *whole
table's* overlays the moment you edit any line of it.  So if you start
typing on a pretty table, the pretty view disappears and your
keystrokes land on the raw source you can now see — no blind editing,
no "Buffer is read-only" error, and crucially no undo break.  (An
earlier design used a =read-only= overlay property; that breaks undo
when you edit raw, toggle pretty, then undo the edit.  The
modification-hook approach is what =org-latex-preview= actually uses.)

Toggle the table back to pretty to re-render from canonical (always
fresh, never a lossy unwrap).

** Resize is lossless

When the window is resized, a debounced idle timer re-renders only the
tables that are *currently pretty*, at the new width — directly from
the canonical source.  Tables you toggled to raw stay raw.  There is no
unwrap/re-wrap step, so the upstream =markdown-table-wrap-unwrap=
idempotency pitfall does not apply.

** Rendering engine

=table-pretty= builds its display strings from cell data (not from
=markdown-table-wrap='s wrapped text output), so it can emit Unicode
box-drawing borders and produce a direct 1:1 raw-line→display-group
mapping (no fragile spacer-row heuristic).  It depends only on
=markdown-table-wrap='s public API: =markdown-table-wrap-cell=,
=markdown-table-wrap-compute-widths=,
=markdown-table-wrap--split-table-row=,
=markdown-table-wrap-visible-width=, and
=markdown-table-wrap-inside-code-fence-p=.

** Detection (no tree-sitter dependency)

Detection is universal line-based (=^[ \t]*|= runs), code-fence guarded
for markdown flavors and =org-in-src-block-p= for org.  It works in
=markdown-mode=, =gfm-mode=, =md-ts-mode=, and =org-mode= without a
markdown tree-sitter parser.

*NOTE:* upstream =markdown-table-wrap= has an open PR #2
(=helper-table-inspection=) adding
=markdown-table-wrap-table-bounds=/=markdown-table-wrap-table-regions=
which do exactly this detection.  Once that PR merges, the vendored
=table-pretty--table-bounds=/=table-pretty--table-regions= here should be
replaced by the upstream functions.

* Commands

| Command                  | Action                                                                            |
|--------------------------+-----------------------------------------------------------------------------------|
| =table-pretty-toggle=    | Point-aware toggle (see below); the main entry point                              |
| =table-pretty-buffer=    | Force pretty on every table in the buffer                                         |
| =table-pretty-region=    | Force pretty on every table in the active region                                 |
| =table-pretty-mode=      | Buffer-local minor mode: wires the resize hook + default-pretty-per-major-mode   |

=table-pretty-toggle= mirrors =org-latex-preview=:

- Point on a table → toggle that table (pretty ↔ raw).
- Point off-table, no region → toggle all tables (if any are pretty,
  make all raw; otherwise make all pretty).
- Active region → toggle tables overlapping the region.
- =C-u= → force pretty on all tables in the buffer.
- =C-u C-u= → force raw on all tables in the buffer.

* Customization

| Defcustom                                   | Default | Meaning                                                        |
|--------------------------------------------+---------+----------------------------------------------------------------|
| =table-pretty-prettify=                    | =t=     | Unicode box-drawing borders; =nil= = plain =\|= pipes          |
| =table-pretty-auto-rewrap-on-resize=       | =t=     | Re-render pretty tables on window resize (lossless)            |
| =table-pretty-rewrap-idle-delay=            | =0.3=   | Seconds to debounce resize re-render (=0= = immediate)          |
| =table-pretty-max-cell-height=             | =nil=   | Cap visual lines per cell (=nil= = unlimited)                  |
| =table-pretty-default-on-major-modes=      | =nil=   | Major modes where tables start pretty when the minor mode is on |

Default state is **off** everywhere: tables start raw and you toggle on
demand.  To make a mode default to pretty, add it to
=table-pretty-default-on-major-modes= and enable =table-pretty-mode=.

* Org mode

Org tables are rendered as GFM-style pipe text in the display (with
=|---+---|= hlines and width cookies =<[lrc]?[0-9]*>= stripped for
*rendering only* — the raw buffer keeps them).  Alignment defaults to
left (org uses cookies, not GFM colons; richer alignment detection is
a future enhancement).

A trailing =#+TBLFM:= line is outside the table region, so it stays
visible and untouched while pretty; formulas are inert while pretty and
live again the moment you toggle to raw.  =table-pretty= does **not**
refuse =#+TBLFM= tables.  Toggling to raw restores full native org table
editing (=org-table-align=, =org-table-next-field=, =TAB=, =C-c C-c=).

* Keybindings

=table-pretty= ships **no** default key (it owns no major-mode map).
Pick one consistent cross-mode key in your config.  The documented
recommendation is =C-c C-x C-k= — the only free, non-surprising
=C-c C-x C-<letter>= slot in both =markdown-mode= and =org-mode=.

** Vanilla Emacs

#+begin_src emacs-lisp
  (require 'table-pretty)
  (define-key markdown-mode-map (kbd "C-c C-x C-k") #'table-pretty-toggle)
  (define-key org-mode-map       (kbd "C-c C-x C-k") #'table-pretty-toggle)
  ;; md-ts-mode has no built-in map variable name you can rely on; use its hook:
  (add-hook 'md-ts-mode-hook
            (lambda () (define-key md-ts-mode-map (kbd "C-c C-x C-k") #'table-pretty-toggle)))
#+end_src

** Doom / evil

Doom users expect =SPC=-prefixed keys.  A consistent cross-mode binding
is =SPC t T= (the global toggle prefix).  Per-mode local-leader aliases
are optional which-key bonuses.

#+begin_src emacs-lisp
  (use-package! table-pretty
    :load-path "site-lisp"
    :after (markdown-mode org)
    :hook (markdown-mode . table-pretty-mode)
    :hook (md-ts-mode    . table-pretty-mode)
    :hook (org-mode      . table-pretty-mode))

  ;; One consistent cross-mode key:
  (map! :leader :prefix "t"
        :desc "Table pretty" "T" #'table-pretty-toggle)

  ;; Optional per-mode local-leader aliases:
  (map! :after markdown-mode :map markdown-mode-map :localleader
        (:prefix ("t" . "toggle")
         :desc "Table pretty" "T" #'table-pretty-toggle))
  (map! :after org :map org-mode-map :localleader
        (:prefix ("b" . "tables")
         (:prefix ("t" . "toggle")
          :desc "Pretty" "p" #'table-pretty-toggle)))
#+end_src

The minor mode (=table-pretty-mode=) only gates the resize hook and the
default-pretty-per-major-mode behavior; =table-pretty-toggle= works
ad-hoc even with the minor mode off (it just won't auto-rewrap on
resize).

* Trying it out

1. Load the library:
   =M-x load-file RET ~/.config/doom/site-lisp/table-pretty.el RET=
2. Open a buffer with a wide pipe table (e.g. =.scratch/demo-tables.md=
   or =.scratch/demo-tables.org=).
3. Put point on a table and run =M-x table-pretty-toggle=.  The table
   redraws as a wrapped, box-drawing view.
4. Toggle again (or edit a cell) to reveal the raw, editable source.
5. Resize the window: pretty tables re-fit; raw tables stay raw.

* Limitations (v1)

- **No markdown markup rendering in the pretty view.**  The pretty
  display shows the canonical text wrapped (e.g. =**bold**= and
  =[text](url)= appear literally), not a fully-rendered markdown view.
  Box-drawing + wrapping + alignment *is* the prettiness.  (A future
  enhancement can extract visible strings + preserve link faces, as the
  pi chat overlay system does.)
- **No link clicking in pretty mode.**  Toggle to raw to follow a link.
  (Clickable links in the pretty view require the geometry work
  documented in =.scratch/Q2-ANALYSIS.md=; deferred.)
- **Org alignment is left-only.**  GFM =:---:= alignment markers are
  respected; org =<r>=/=<c>= cookies are not yet read.
- **Multi-line headers** (lines before the separator beyond the first)
  are not merged; the first header line is used.

* Upstreaming

=table-pretty= is designed to merge into =markdown-table-wrap= later as
=markdown-table-wrap-pretty.el= (clean public entry points, no pi/doom
deps, GPL-3.0-or-later).  Coordinate with upstream PR #2
(=helper-table-inspection=), which is complementary: that PR is about
safely *rewriting* table text; =table-pretty= is about *displaying* a
pretty rendering over canonical text without rewriting it.
